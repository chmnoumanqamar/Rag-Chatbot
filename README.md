# Simple RAG Chatbot

An educational, modular, and production-ready **Retrieval-Augmented Generation (RAG) Chatbot** in Python.

This project demonstrates how a chatbot can answer user questions accurately by retrieving information from user-provided documents instead of relying purely on a model's static pre-trained knowledge. It is designed to be simple enough for a student to understand and explain in a viva, while adhering to professional software engineering and AI design patterns.

## What is RAG?

**Retrieval-Augmented Generation (RAG)** is an AI framework that grounds Large Language Models (LLMs) on external, verifiable data sources.

### Why is RAG needed?
1. **Eliminating Hallucinations**: Standard LLMs generate probable text, which can lead to confident yet completely fabricated answers. RAG forces the LLM to base answers *strictly* on retrieved facts.
2. **Access to Private & Fresh Data**: LLM training datasets have static knowledge cutoffs and cannot access private documents. RAG allows LLMs to answer queries using your specific notes, PDFs, or internal documentation without retraining or fine-tuning the model.
3. **Cost & Computation Efficiency**: Indexing documents in a vector store is orders of magnitude faster and cheaper than fine-tuning or training LLMs.
4. **Source Attribution & Explainability**: Every answer generated by RAG can cite the exact document, page number, and chunk it originated from.

## How It Works

The complete RAG pipeline consists of two primary phases: **Ingestion (Indexing)** and **Retrieval & Generation (Querying)**.

```text
======================= 1. INGESTION PHASE =======================

Documents (.pdf, .txt, .docx, .md)
      │
      ▼
Text Extraction (pypdf, python-docx)
      │
      ▼
Text Cleaning & Normalization (utils.py)
      │
      ▼
Text Chunking (Recursive Splitter: 800 chars, 100 overlap)
      │
      ▼
Embedding Generation (OpenAI text-embedding-3-small)
      │
      ▼
Vector Store Persistence (ChromaDB in ./vector_db)


================= 2. RETRIEVAL & GENERATION PHASE =================

User Question ("What is machine learning?")
      │
      ▼
Contextual Query Reformulation (resolves follow-ups / pronouns)
      │
      ▼
Question Embedding (Vector representation)
      │
      ▼
Similarity Search (Cosine / L2 distance search in ChromaDB)
      │
      ▼
Top-K Relevant Chunks (with metadata: source, page, chunk_id)
      │
      ▼
Strict Grounded Prompt Construction (prompts.py)
      │
      ▼
Large Language Model (ChatOpenAI: gpt-4o-mini)
      │
      ▼
Answer with Source Citations & Provenance
```

## Key Features

- **Multi-Format Document Support**: Seamlessly parses `.txt`, `.pdf` (page-by-page via `pypdf`), `.md` (Markdown), and `.docx` (Microsoft Word).
- **Persistent Vector Database**: Embeddings and metadata are persisted locally in `vector_db/` using **ChromaDB**, eliminating redundant computation across app restarts.
- **SHA-256 Duplicate & Modification Detection**: Identifies whether documents are new, unchanged, or modified. Automatically skips unchanged files and re-indexes modified files.
- **Strict Anti-Hallucination Prompting**: If retrieved context does not contain the answer, the assistant explicitly states that the information is unavailable rather than fabricating details.
- **Transparent Source Citations**: Answers display exact source filenames, chunk IDs, page numbers (for PDFs), and similarity scores.
- **Conversational Memory & Follow-Up Handling**: Retains recent dialogue history (`MAX_HISTORY = 10`) and rephrases pronoun-heavy follow-up questions (e.g., *"What are its main types?"*) into standalone search queries.
- **In-Chat Commands**: Supports interactive commands in Chat Mode: `sources`, `clear`, `help`, and `exit`.
- **Zero-Crash Fallback Mode**: If no OpenAI API key is configured, the application smoothly switches to deterministic local offline embeddings and demo responses so you can inspect chunking, vector indexing, and retrieval mechanics without errors.
- **Security & Logging**: Environment variables protect API keys; comprehensive events are logged to `rag_chatbot.log` (excluding sensitive data or secrets).

## Configuration (.env)

Create a `.env` file in the root directory by copying `.env.example`:

```bash
# On Windows PowerShell:
Copy-Item .env.example .env

# On Linux / macOS:
cp .env.example .env
```

Open `.env` and add your OpenAI API key:

```env
# OpenAI API Configuration
OPENAI_API_KEY=sk-proj-yourActualKeyHere
OPENAI_MODEL_NAME=gpt-4o-mini
OPENAI_EMBEDDING_MODEL=text-embedding-3-small

# RAG Hyperparameters
CHUNK_SIZE=800
CHUNK_OVERLAP=100
TOP_K=4
SIMILARITY_THRESHOLD=0.25
MAX_HISTORY=10

# Debug & Development
DEBUG_MODE=False
```

> **Note**: If you do not have an OpenAI API key immediately, the project will still run in **Offline Demo Mode**, allowing you to test document ingestion, chunking, indexing, and vector search.

## Running the Application

Launch the interactive CLI:

```bash
python main.py
```

### Main Menu Options

```text
==================================================
                SIMPLE RAG CHATBOT
==================================================

1. Add Documents
2. Build Knowledge Base
3. Ask Questions
4. View Knowledge Base Info
5. Clear Knowledge Base
6. Exit

Enter your choice (1-6):
```

### Step-by-Step Walkthrough

1. **Option 1 (Add Documents)**: Enter the path to any `.txt`, `.pdf`, `.md`, or `.docx` file (e.g., `data/documents/sample_ai_notes.txt`). The system validates the document and stages it.
2. **Option 2 (Build Knowledge Base)**: Chunks all staged documents, computes vector embeddings, and stores them in ChromaDB.
3. **Option 3 (Ask Questions)**: Enters interactive Chat Mode. Ask any question about your documents.
4. **Option 4 (View Knowledge Base Info)**: Inspect total indexed documents, total chunks, embedding provider, and file registry.
5. **Option 5 (Clear Knowledge Base)**: Clears the ChromaDB collection and index metadata with confirmation.
6. **Option 6 (Exit)**: Closes the application cleanly.

## Viva & Technical Interview Guide

Here are common questions asked during academic viva examinations or technical interviews regarding RAG architectures:

### 1. What is the role of Vector Embeddings in RAG?
> **Answer**: An embedding model converts textual chunks into dense numerical vectors in a high-dimensional space (e.g., 1536 dimensions for `text-embedding-3-small`). Semantically similar texts are placed close together in this vector space, allowing mathematical distance metrics (like Cosine Similarity or Euclidean Distance) to retrieve conceptually relevant information even when exact keywords differ.

### 2. Why do we need Chunk Overlap?
> **Answer**: If a document is split strictly at fixed character boundaries, important contextual ideas or sentences spanning the boundary could be severed in half. `CHUNK_OVERLAP` (e.g., 100 characters) ensures that boundary sentences appear in both adjacent chunks, preserving semantic coherence across chunks.

### 3. How does RAG prevent LLM Hallucinations?
> **Answer**: By instructing the LLM via system prompts that it must act exclusively as a synthesizer of the retrieved context. If the answer is not present in the retrieved chunks, the prompt forces the LLM to reply that the information is missing rather than generating unverified assumptions.

### 4. What is the difference between Fine-Tuning and RAG?
> **Answer**:
> - **Fine-Tuning**: Modifies model weights by training on specialized datasets. It is ideal for teaching a model a specific style, tone, or complex domain jargon, but is expensive, slow to update, and prone to hallucinations.
> - **RAG**: Does not modify model weights. It dynamically injects external knowledge into the prompt context at query time. It is real-time, cheap to update, private, and fully auditable with citations.

### 5. What is the purpose of SHA-256 Document Hashing in this project?
> **Answer**: To prevent unnecessary re-embedding of unchanged documents. Generating embeddings incurs time and API costs. By hashing each file, the system checks whether a file has been modified before deciding whether to skip or re-index it.

## Troubleshooting

| Problem | Cause | Solution |
| :--- | :--- | :--- |
| `Authentication error / Invalid API key` | `OPENAI_API_KEY` in `.env` is missing or incorrect. | Ensure your active key is added to `.env` without quotes or spaces. |
| `PDF contains no extractable text` | PDF is a scanned image without an OCR layer. | Use text-based PDFs or run OCR on scanned documents. |
| `Knowledge base is empty` | Queried chatbot before building the index. | Select `Option 1` to add documents and `Option 2` to build the knowledge base first. |
| `ModuleNotFoundError` | Virtual environment is not activated or dependencies are missing. | Run `pip install -r requirements.txt`. |
